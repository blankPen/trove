# 0003 · web 只读本地 vault，远端同步由用户显式触发

- 日期：2026-11-04
- 状态：已接受

## 上下文

trove 支持多设备 + WebDAV/S3 远端。统一索引 `library/index.json` 已经把
跨设备会话合并成一个视图（含 `sources` 设备列表），`trove sync` / daemon
负责把远端数据拉到本地。

一个 web 界面自然的想法是「打开就看到最新」，即自动拉远端。

## 决策

web **只读本地 vault**。远端同步是用户显式动作：

- 「立即同步」按钮 → web 进程内调 `sync()`（见 ADR-0002）
- daemon 状态只读展示（`daemon.status.json`）
- 不在页面加载时自动触发任何同步

## 理由

- 同步是 trove 的核心不变量：daemon 与手动 sync 共享一把锁、
  有增量水位、有跨设备合并规则。web 自动拉远端意味着每次打开页面
  都可能触发一次 30s+ 的写操作，还可能撞锁。
- 「打开就最新」的成本是「打开就可能阻塞、可能失败、可能锁冲突」。
  用户手点一下同步按钮，代价小得多。
- 统一索引已经把跨设备合并做完了 —— web 读它就够了，不需要自己懂远端。

## 代价

- 远端有更新时，web 看到的是旧数据，直到用户点同步（或等 daemon 跑完）。
  UI 上要有明确的「上次同步时间」和 staleness 提示。
